Instrumento → Driver (traductor) → Framework → Protocolo único CSM → Web Server ↔ Backend → BD, e integración con sistemas externos.

2 · El driver es un traductor

Cada instrumento habla su propio protocolo. El driver abre el puerto, recibe, traduce y empaqueta la info para el backend.

3 · Framework: todo se unifica en el protocolo CSM

El framework transforma todos los protocolos en uno solo (CSM) para que el web server hable con el BE, aunque los equipos sean distintos.

4 · Evolución de servicios: Commserver → CSLite

Antes un solo servicio Windows (Commserver) manejaba todos los drivers. Ahora cada instrumento tiene su servicio independiente (CSLite).

5 · Integración con HIS / LIS (bidireccional + ACK)

El sistema recibe datos de paciente (ADT) y envía resultados vía HL7/ASTM. Cada mensaje se confirma con ACK.
